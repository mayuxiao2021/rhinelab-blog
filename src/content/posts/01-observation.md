「再加个暗色模式」是很多主题的最后一步，也是翻车最多的一步。把亮色变量反相，会得到一套发灰、发蓝、对比度不足的界面。这里记录本主题的实际取舍。

## 两套令牌都来自同一份基线

| 语义 | 亮色 | 暗色 | 说明 |
| --- | --- | --- | --- |
| 背景 | `#eae5e1` | `#11181b` | 暖纸 ↔ 冷墨绿黑 |
| 纸面 | `#edebe4` | `#202a2f` | 卡片与面板 |
| 正文 | `#080a08` | `#e0e3dc` | 正文与标题共用 |
| 辅助 | `#77756d` | `#a6b0b1` | 日期、字数、说明 |
| 结构线 | `#aaa59a` | `#536166` | 1px 分隔线 |
| 黄铜强调 | `#9b7247` | `#c5a16b` | 编号、当前项、链接 |

暗色不是反相：背景取带绿倾向的近黑，纸面比背景亮两档，强调色反而调亮，因为深色背景会"吃掉"中间调。

## 对比度不是越多越好

正文对比度做到 **14:1** 以上会开始刺眼。本主题的正文在亮色下约 15:1、暗色下约 11:1，辅助文字控制在 4.5:1 以上但不追高。真正需要高对比的是**焦点环**：

```css
:where(a, button, input, [tabindex]):focus-visible {
  outline: 2px solid var(--rl-amber);
  outline-offset: 2px;
}
```

用 `:where()` 把特异性压到 0，任何组件都能覆盖它；用 `:focus-visible` 而不是 `:focus`，鼠标点击不出现丑陋的环。

## 减少动态效果是硬约束

扫描线、脉冲点、卡片悬停位移全部在 `prefers-reduced-motion: reduce` 下关闭：

```css
@media (prefers-reduced-motion: reduce) {
  .rhine-hero__scan { display: none; }
  .rl-progress__tick { transition: none; }
  .rl-card, .rl-card:hover { transform: none !important; }
}
```

这不是锦上添花：对前庭敏感用户，持续位移是**生理不适**，不是审美偏好。

## 被否掉的两个方案

1. **全屏颗粒噪点**：好看，但滚动时每帧重绘，移动端掉帧；改为静态的「准星阵列」背景层。
2. **进入页面时的逐字输入动画**：首屏延迟 300ms 以上，且屏幕阅读器体验差；保留语义文本，只做装饰性扫描线。

> 结论：档案感来自**结构与字距**，不来自特效数量。删掉的特效比加上的更能说明一个主题是否想清楚。
